## Confirmed defects

### F1 — Release build cannot work offline despite shipping a service worker (High)
`scripts/workbox-dist.config.cjs:11-24` precaches `index.html, boot.js, pdf-runtime.js, manifest.json, style.css, opencoursedeck.js, chunks/**, assets/**, vendor/**, data/**, docs/**` — but not `src/styles/index.css` or `src/workers/**`. The app shell loads the flattened release stylesheet at `index.html:67` (`<link rel="stylesheet" href="./src/styles/index.css">`) and resolves workers at `src/core/workerAssets.js:9` (`new URL('src/workers/…', baseURI)`). Both are runtime fetches, never precached. Verified by serving a from-scratch release build, registering the worker, then going offline: stylesheet and worker fetches fail (`net::ERR_INTERNET_DISCONNECTED` in the captured evidence); the offline page loses all component styling. Contradicts README "offline-friendly", DESIGN.md "100% offline functionality", and GEMINI.md "All core features must work 100% offline". Fix: add `'src/styles/index.css'` and `'src/workers/*.worker.js'` to `globPatterns` (workers are ≤ 5 MB each, under `maximumFileSizeToCacheInBytes`). Regression: the existing offline test in `tests/runtime-wiring.test.js` plus a new offline-reload assertion (the project's dist-browser-smoke can be extended).`

### F2 — `desktop-release.yml` executes `cd far` against a directory that does not exist (High)
`.github/workflows/desktop-release.yml:37,42,48`. The repo root has no `far/` directory (`git ls-files 'far/*'` empty; `test -d far` false). Every desktop-release run fails at "Install dependencies". This workflow is triggered by `v*` tags — a tagged release silently produces no desktop artifacts. Fix: delete the three `cd far` lines. Fix test: `act`/workflow_dispatch dry-run, or simply the next tag push.

### F3 — Repository browser-smoke asserts a retired page title (High, gate integrity)
`scripts/browser-smoke.cjs:193` waits for `text === 'Courses'`; the Courses route now renders `Course Catalog` (`src/views/coursesRoute.js` page title; verified in the live session). The check fails deterministically (`npm run smoke:browser` → exit 1). CI runs it (verify.yml:286) but the observed run did not block the pipeline, meaning a red gate is being tolerated rather than fixed. Fix: update the expected string to `'Course Catalog'` (or assert on `[data-route]`/heading role rather than exact title).

### F4 — Closing the last modal leaves body scroll locked (Medium, fixed in this session)
`src/ui/overlays.js:138-143` (pre-fix). `stackNow` captured the array reference *before* reassignment, so `!stackNow.length` was always false when the last modal closed; `document.body.style.overflow` stayed `'hidden'` after the final modal. Reproduced in unit test (new case in `tests/app-core.test.js`), then fixed (one-line change: read the post-filter stack), then verified three ways: unit (773/773), lint, and a live Playwright session importing the real `Modal` in the served app — opened `hidden`, closed `''`, remaining stack 0. Fix is `src/ui/overlays.js:141-143`; regression test is `tests/app-core.test.js:169-187`.

### F5 — Restoring flashcards does not invalidate the live deck cache (High, unfixed — review finding)
`progress.js:757-761` writes restored decks to IndexedDB + localStorage, but `flashcards.js:59-101` keeps serving its in-memory `memoryStore` once hydrated. A user who imports a backup while a deck is already loaded sees the stale deck; the next `addCard`/`reviewCard` (`flashcards.js:121-158`) persists the stale deck over the restored one. Reproduced independently by the storage reviewer with an isolated DOM probe. Fix: add a non-destructive `invalidate()`/`replaceCache()` to `FlashcardDeckManager` and call it after a successful import (do not reuse `reset()`, which also wipes persistence). Test: import with an already-hydrated manager, assert the restored deck is visible and survives the next review.

### F6 — Flashcard keyboard shortcuts hijack native button activation (Medium)
`flashcards.js:327-337`: the container-level `keydown` handler excludes text inputs but not buttons. With an unrevealed due card present, Enter or Space on the focused **New card** button is `preventDefault`ed and reinterpreted as "Show Answer" (verified in the real browser session and by the feature reviewer's DOM probe). Keyboard users cannot open the creation form. Fix: skip handling when `event.target.closest('button, a, [role="button"], [contenteditable]')` is non-null.

### F7 — PDF viewer load race can commit a stale document (Medium)
`pdf.js:235-304`: two overlapping `PDFViewer.load()` calls both proceed; whichever finishes last wins regardless of call order. `State.renderToken` guards rendering, not document identity; the identity-hardening wrapper (`src/core/pdfIdentityHardening.js:155-170`) serializes nothing. Also `destroyPDFViewer` (`pdf.js:1508-1527`) does not cancel a pending `loadingTask`, so a cancelled route can still assign `State.pdfDoc` after teardown. Fix: capture a load-generation counter before `await` and discard stale commits, plus `loadingTask.destroy()` in the teardown path. (Medium severity because route navigation triggers loads; a guard test belongs in `tests/pdf.test.js`.)

### F8 — Persian language option changes document metadata without translating UI (Medium)
`src/views/settingsRoute.js:319-329` wires the `<select>` to `setCurrentLang('fa-IR')`, which sets `html lang="fa-IR" dir="rtl"` and persists `ocd_lang`/`ocd_dir` (`src/core/locale.js:113-130`). But `docs/architecture.md:77-84` confirms view strings are not keyed through the locale engine — the UI stays English. Screen readers may switch pronunciation rules for English text; users get no translation. Fix options: hide/disable the option until wiring exists, or ship a partial dictionary and mark the feature beta.

## Source-backed risks (evidence in code, dedicated regression test still needed)

- **Library destructive-write path** — `src/features/userLibrary.js:137-149`: `loadLibrary()` swallows any read error into `emptyLibrary()`; `upsertCourse`/`addTopic`/`removeCourse` (`:319-373`) then persist that empty snapshot. A transient IndexedDB read failure followed by a successful write replaces the whole `ocd_user_library` setting. Storage reviewer flagged High; sequence not reproduced end-to-end.
- **Progress writes silently fall back to localStorage** — `bridge.js:560-594`: non-quota IDB failures fall through to localStorage and still report success; reads prefer IndexedDB exclusively once it recovers, so an acknowledged write can become invisible. Needs a reconciliation pass or explicit rejection.
- **Annotation fallback resurrection** — `src/core/bridgeHardening.js:65-112`: after a successful authoritative save, stale localStorage fallback records for the same docId are merged back on read; a deleted annotation can reappear.
- **Auxiliary DB lifecycle** — `src/core/auxiliaryDbLifecycle.js:76-86` closes MediaStorage's connection on reset, but `src/features/mediaStorage.js` only invalidates `_cachedDB` on `versionchange`; subsequent operations reuse the closed handle until reload.
- **Studio dual restore source** — `canvas.js:190` (`ocd_canvas_board`) vs `src/views/studioRoute.js:145,425` (`ocd_studio_board`) both call `Canvas.loadState` on mount; last writer wins.
- **3D graph activation after unmount** — `src/views/studioRoute.js:582-588` awaits `DB.getAllNotes()` before assigning `spatialGraphInstance`; unmount during that await disposes nothing and the continuation mounts into detached DOM with RAF/window listeners (`spatialKnowledgeGraph.js:204-209,294-297`).

## Architecture assessment

The hybrid global-namespace + ES-module design is coherent and the hardening layer (`src/core/*Hardening*`, `storageSafety`, `mutationRetry`, `operationContext`) is unusually disciplined for a vanilla app. `src/index.js:46-52` installs safety layers before any feature module; feature chunks are genuinely lazy (`runtime-wiring.test.js` pins the eager/feature split). Debt is concentrated in: (a) two namespaces for the same feature (Plasma* legacy + OpenCourseDeck), (b) 3.8k-line `app.js` still holding the shell, and (c) documented module conventions drifting from reality (`docs/architecture.md:69-71` names a nonexistent `src/lib/routeListeners.js`).

## Strengths worth keeping

- Defense-in-depth storage design (encryption envelope, per-DB salt, PBKDF2, migration receipts, quota-aware fallbacks) is well above typical vanilla-app practice.
- CI verify.yml is unusually rigorous: pinned SHAs, reproducible npm ci, adversarial-release tests, SBOM + attestation + verification of both.
- Test suite covers real user flows (bookmarks, PDF page notes, Studio autosave, mini-player handoff) rather than implementation trivia; test ids and jsdom setup are clean.
- Release identity checks (tag/commit/package triple-match) prevent the classic "moved tag" mistake.
- CSP is consistently strict across dev header, meta, and Tauri config (`object-src 'none'; base-uri 'none'; frame-ancestors 'none'`).

## Design overhaul (2026-09-18, verified)

A full visual pass over `src/styles/` — tokens, themes, accents, base, layout, components, views, enhancements, notes-enhancements, utilities, player. Every change below was measured, not eyeballed (the vision model was unavailable, so all visual claims are computed: contrast math, palette extraction, and DOM measurement).

- **Contrast — 6 WCAG AA failures → 0.** Root cause was `--accent-light` text on `--accent-muted` tints at 3.71:1. The fix is a new `--accent-on-tint` token (`color-mix(in srgb, var(--accent-light) 70%, white)` → 6.55:1) with darkened overrides for light accents (cyan `#0e7490`, amber `#b45309`, emerald `#047857`) in `accents.css`, applied at all 25 text-bearing sites. An earlier attempt that mixed the accent *into* the background was rejected — the math showed it worsens contrast (3.39 → 2.21).
- **Light theme rebuilt.** The old light theme was flat `#fff`/`#f5f5fa`; it is now cool violet-tinted neutrals with tinted shadows. Measured result: accent-hue pixels 0% → 2.4–5.4%, saturated pixels 3–5% → 38–46%. Dark-theme shadows are tinted to `rgba(8,4,26,*)` instead of pure black.
- **Sub-10px text eliminated.** The cause was `kbd { font-size: 0.78em }` compounding to 9.36px. Added a `--text-floor: 11px` token used via `max()` in the `.text-*` helpers and `kbd`; the 9.36px case is gone.
- **Typography.** `.page-title` is now fluid `clamp(1.75rem → 2.5rem)` in `--font-display` (Playfair), and the `.view .page-header` override that forced `font-sans 1.4rem` was removed. Impossible font-weights 650 → 600 and 750 → 700 (Inter ships static weights only). Tabular figures on `.badge` and `.storage-label`.
- **Craft details.** Double-bezel (`--radius-bezel-outer`) on `.card`; a single `--press-scale: 0.97` replaces the 0.96/0.98/0.985/0.995 spread; `--space-1_5` (6px) and `--space-14` (56px) promoted to tokens; `kbd` radius now `var(--radius-sm)`.

Verification: 783/783 tests, contrast 0 failures, 0px horizontal overflow on all 15 routes, `check:encoding`, `check:workflows`, `check:generated`, `build:release` (180 precached), HTTP smoke 93/93, and `smoke:browser` all green.

Note on `dist/`: it is gitignored build output. It was rebuilt (`npm run build:release`) so `check:generated` matches the working tree after the source fixes above; the offline globs were first proven in an isolated temp copy, and the user's pre-existing `dist/` was regenerated rather than overwritten by an unverified build.
